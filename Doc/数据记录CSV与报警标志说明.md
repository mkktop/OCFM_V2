## 1. 概述

设备按固定周期将一组工况数据以 CSV（逗号分隔）格式追加写入 SD 卡，用于历史追溯、数据导出与监管留档。满足 HJ 15-2019《超声波明渠污水流量计技术要求及检测方法》对运行数据长期保存的要求。

| 项目 | 说明 |
|------|------|
| **存储路径** | `/data/YYYY/MM/DD.csv`（按日期分文件） |
| **记录周期** | 默认 60 秒一条（`DATA_RECORD_INTERVAL_MS`） |
| **保留期限** | 配置默认声明 365 天（`retention_days = 365`），但清理函数当前**未接入，实际不会自动清理**，数据持续写入直至 SD 卡写满 |
| **文件编码** | ASCII，行尾 `\r\n`（Windows 换行），UTF-8 友好 |
| **首行** | CSV 表头，定义各列字段名 |

CSV 表头（首行）固定为：

```
timestamp,water_level,instant_flow,total_flow,total_time,temperature,alarm_flags
```

## 2. CSV 字段说明

| 列序 | 字段名 | 单位 | 格式 | 含义 |
|:---:|------|------|------|------|
| 1 | `timestamp` | — | `YYYY-MM-DD HH:MM:SS` | 记录时刻（设备 RTC 时间） |
| 2 | `water_level` | m | 3 位小数 | 实测水位（安装高度 − 测距）；传感器离线时为 `0` |
| 3 | `instant_flow` | m³/h | 6 位小数 | 瞬时流量（内部 L/s × 3.6 换算） |
| 4 | `total_flow` | m³ | 6 位小数 | 开机以来的累计流量（double 精度） |
| 5 | `total_time` | 秒 | 整数 | 累计计量时间 |
| 6 | `temperature` | °C | 1 位小数 | 介质/环境温度；传感器无温度时为 `0` |
| 7 | `alarm_flags` | — | 整数 | 报警标志位（位掩码，详见第 3 节） |

> **注：** 报警判定基于**瞬时流量（m³/h）**与设定的报警阈值比较，即第 3 列与第 7 列同源。

## 3. alarm_flags 报警标志位定义

`alarm_flags` 是一个 **位掩码（bitmask）**，共 4 个有效位，每 1 位对应 1 路报警是否处于**触发中**状态。该位在记录数据时由 `log_task` 实时读取各报警状态组装而成（[Core/Src/freertos.c:276-281](../Core/Src/freertos.c#L276-L281)）：

```c
uint16_t flags = 0;
if (app_alarm_get_state(ALARM_TYPE_AH)  == ALARM_STATE_ACTIVE) flags |= 0x0001;
if (app_alarm_get_state(ALARM_TYPE_AL)  == ALARM_STATE_ACTIVE) flags |= 0x0002;
if (app_alarm_get_state(ALARM_TYPE_AAH) == ALARM_STATE_ACTIVE) flags |= 0x0004;
if (app_alarm_get_state(ALARM_TYPE_AAL) == ALARM_STATE_ACTIVE) flags |= 0x0008;
```

| 位 | 掩码 | 报警类型 | 通俗含义 | 对应继电器 |
|:---:|:---:|:---:|------|------|
| bit0 | `0x0001`（十进制 **1**） | AH  | 流量偏高（超过上限）   | relay1 / PA4 |
| bit1 | `0x0002`（十进制 **2**） | AL  | 流量偏低（低于下限）   | relay2 / PA5 |
| bit2 | `0x0004`（十进制 **4**） | AAH | 流量严重偏高（超过上上限） | relay3 / PA6 |
| bit3 | `0x0008`（十进制 **8**） | AAL | 流量严重偏低（低于下下限） | relay4 / PA7 |

- bit4 ~ bit15 目前**未使用**，预留扩展。
- 值为 `0` 表示该时刻**没有任何报警**处于触发状态。
- 同一时刻可能多个报警同时触发，故 `alarm_flags` 的值是若干掩码之和。

> 该标志位不仅用于写入，历史查询时还可用 `filter_alarm_only` + `flags_mask` 筛选“仅含报警的记录”（[data_recorder.c:341](../Drivers/File/data_recorder.c#L341)）。

## 4. 数值速查表

无需理解位运算，直接按下表对照即可。日常最常见的是 **0（正常）** 与 **5（高报叠加）**。

| 数值 | 二进制 | 含义 |
|:---:|:---:|------|
| **0** | `0000` | 一切正常，无报警 |
| **1** | `0001` | 流量偏高（上限 AH） |
| **5** | `0101` | 流量偏高且严重偏高（AH + AAH，最常见的高报叠加） |
| **2** | `0010` | 流量偏低（下限 AL） |
| **10** | `1010` | 流量偏低且严重偏低（AL + AAL，低报叠加） |
| 4 | `0100` | 仅严重偏高（理论上短暂出现，AAH 触发但 AH 已恢复） |
| 8 | `1000` | 仅严重偏低（理论上短暂出现，AAL 触发但 AL 已恢复） |
| 15 | `1111` | 四路报警全部触发（极端情况） |

> **说明：** AH 与 AAH 同属“高报侧”，AL 与 AAL 同属“低报侧”，阈值存在包含关系（详见第 5 节）。因此正常运行只会出现 `0 / 1 / 5 / 2 / 10` 等几种组合，**不会出现 `3`（同时偏高又偏低）这类矛盾值**。偶发的 `4` 或 `8` 出现在报警恢复过渡瞬间（高报先恢复上限、再恢复上上限的间隔周期内）。

## 5. 报警触发与恢复阈值

报警判定由 [app_alarm_update()](../App/app_alarm.c) 每秒执行一次，基于**瞬时流量（m³/h）**与设定阈值比较。为避免流量在阈值附近抖动导致继电器频繁吸合/断开，每路报警均设有**滞回（回差）**：

| 报警类型 | 触发条件 | 恢复条件 | 回差来源 |
|------|------|------|------|
| AH（上限）   | 流量 ≥ AH   | 流量 < AH − DH   | 独立 DH |
| AAH（上上限） | 流量 ≥ AAH  | 流量 < AAH − DH  | **与 AH 共用 DH** |
| AL（下限）   | 流量 ≤ AL   | 流量 > AL + DL   | 独立 DL |
| AAL（下下限） | 流量 ≤ AAL  | 流量 > AAL + DL  | **与 AL 共用 DL** |

> **关键：** AAH / AAL 没有独立的回差值，分别与 AH / AL 共用 DH / DL。
>
> **离线保护：** 传感器离线时，所有报警立即解除、继电器全部断开，`alarm_flags` 归 `0`。

**参数含义：**

| 参数 | 说明 |
|------|------|
| `AH` / `AAH` | 上限 / 上上限报警阈值（m³/h），AAH > AH |
| `AL` / `AAL` | 下限 / 下下限报警阈值（m³/h），AAL < AL |
| `DH` | 高报侧回差（m³/h），AH 与 AAH 共用 |
| `DL` | 低报侧回差（m³/h），AL 与 AAL 共用 |

以上阈值与回差均可通过设置菜单或 Modbus 寄存器（报警值分组 `0x000E ~ 0x0019`）配置。

## 6. 读取示例与解读

### 示例 1：正常工况

```
timestamp,water_level,instant_flow,total_flow,total_time,temperature,alarm_flags
...
2026-06-16 14:30:00,0.523,12.450000,384.120000,3600,24.5,0
```

解读：14:30:00 时刻，水位 0.523 m，瞬时流量 12.45 m³/h，累计流量 384.120 m³，累计计量 3600 秒，温度 24.5 ℃，`alarm_flags = 0` → **无报警，工况正常**。

### 示例 2：高报叠加

```
2026-06-16 14:31:00,0.812,28.600000,392.050000,3660,24.6,5
```

解读：`alarm_flags = 5 = 1 (AH) + 4 (AAH)` → **瞬时流量 28.6 m³/h 已超过上限，并进一步超过上上限，AH 与 AAH 两路高报继电器同时动作**。

### 示例 3：低报叠加

```
2026-06-16 14:32:00,0.105,1.200000,392.380000,3720,24.6,10
```

解读：`alarm_flags = 10 = 2 (AL) + 8 (AAL)` → **瞬时流量 1.2 m³/h 已低于下限，并进一步低于下下限，AL 与 AAL 两路低报继电器同时动作**。

## 7. 常见问题（FAQ）

**Q1：为什么报警值是 5 而不是 1？**
A：流量是连续变化的，持续上升时会先过 AH（此时记 `1`），再过 AAH，两个报警同时处于触发态，标志位即变为 `5`。流量回落时则会先退出 AAH 变回 `1`，再退出 AH 变回 `0`。

**Q2：alarm_flags 和继电器输出有什么关系？**
A：一一对应。标志位中有 `1`（bit0）即上限继电器吸合；为 `5` 即上限、上上限两路继电器均动作。现场接线与继电器对应的受控设备（如阀门、泵、声光报警器）据此联动。

**Q3：屏幕上显示文字，CSV 里为什么是数字？**
A：现场屏幕以“正常 / 偏高 / 偏低”等文字直观展示；CSV 采用位掩码数字是为了节省存储空间、便于程序批量解析与历史报警筛选，也满足长期保存（≥1 年）的监管要求。

**Q4：如果一直显示 0 是否正常？**
A：正常，说明这段时间瞬时流量始终处于设定的上下限区间内。若怀疑阈值设置不当导致“从不报警”，可在设置菜单中检查 AH / AL / AAH / AAL 及回差 DH / DL 是否合理。

**Q5：传感器离线时 alarm_flags 会怎样？**
A：传感器离线时所有报警立即解除、继电器断开，`alarm_flags = 0`，同时水位列可能记为 `0`，需结合瞬时流量列综合判断是否为真实停流还是传感器掉线。

**Q6：怎么从 CSV 中筛出所有发生过报警的记录？**
A：筛选 `alarm_flags` 列 **不为 0** 的所有行即可；如需精确到某一路报警（如仅上上限 AAH），筛选 `alarm_flags & 0x0004 != 0`（即该列数值按位与 4 不为 0）的行。
